# NanoTrack 初始化输入帧快照设计

## 目的

在不改变跟踪、状态机和伺服输出语义的前提下，保留 NanoTrack 初始化时实际收到的一帧图像，用于检查 RGB/BGR 通道、1920x1080 分辨率、5760 字节步长、帧来源以及初始化框与图像是否匹配。

## 方案比较

1. **只保存 `STATE_INIT_TRACK` 对应的算法输入帧（采用）**：在 RGB 转 BGR 完成后、调用 `LongTermRuntime::initialize()` 前同步保存一次 PNG。它精确对应建立模板的图像，写盘次数最少。
2. 同时保存初始化帧和首个 `STATE_DO_TRACK` 帧：能额外比较相邻帧，但会增加诊断逻辑和工件，第一轮没有必要。
3. 连续保存多帧或视频：信息最多，但会影响实时路径和存储，不适合当前吊舱诊断。

## 具体行为

- 保存内容：`make_bgr_view()` 生成、即将传给 NanoTrack 的完整 BGR 图像，不画框、不缩放、不再次换色。
- 触发条件：每次新的 `STATE_INIT_TRACK` 成功完成图像转换后保存一张；普通跟踪帧不保存。
- 输出路径：部署目录的 `log/` 下使用固定、容易获取的诊断文件名；新一次初始化覆盖上一张，避免持续占用空间。
- 日志：记录保存是否成功、绝对路径、宽、高、通道数、步长及本次初始化框。
- 失败处理：PNG 保存失败只记录错误，不使 `do_tracker_detector()` 返回失败，不改变跟踪任务。
- 数据边界：该图片只证明进入 NanoTrack 前的完整帧；它不能单独证明模型裁剪、RKNN 输入张量或宿主伺服控制正确。

## 不包含

- 不保存连续帧、视频、搜索裁剪或模型张量。
- 不修改 `rect_show`、`track_box_result.rect[0..4]`、质量阈值、预测器或控制行为。
- 不把诊断图片提交 Git。

## 验证

- 主机侧测试确认仅初始化命令触发、保存失败不影响返回语义。
- A6 交叉编译成功后部署诊断产物。
- 人工下发一次跟踪初始化，核对生成 PNG 的尺寸、颜色、内容和初始化框日志。
